# 采购当前快照与关联丢失的边界

基线为 PR #61 `ae1899da9fd2af0a4b9d2e8d8e425f9c587c3479`。
本轮只在现有核验范围内补充采购检查，并纠正合法取消后的历史关联误报；不自动恢复或创建关联。

## 可可靠核对的当前事实

有关联的 `PurchaseOrder.doc_revision` 明确声明其当前单据版本。seed、采购变更、补购和取消
均写入对应 `DocRevision`；取消不能成为当前快照缺失的例外。查询按单据类型、ID、版本精确联接，
旧版本、其他单据及另一单据类型的同名 ID 都不能替代当前快照。

所有这些写入路径都记录 `material_id` 和整数 `ordered_qty`。逐张核对这两个字段，可发现同一
MO 下两张采购单各增减一单位、总材料数量不变的漂移。缺失字段、非对象内容及布尔数量也需人工核对。
报告只提供 `manual_review` 和单据身份，不从当前行反向补造快照，不修改采购或重新提交订单。

这不是完整快照真实性审计：到料数量/状态属于另行记录的执行事实；供应商和父生产单也没有统一
出现在全部快照写入形状中，本轮不比较这些字段。非当前历史快照缺失不阻塞当前事实核验。

## 合法取消与混合库存订单

`assess_downstream` 排除已取消单据，后续提交只重链未取消单据。这与 `PLAN_REVISION.md` 的
不变量 9 一致。因此，取消 MTO 剩余量后继续修改 STOCK 行时，取消单据仍停留在取消时的订单版本，
应当通过关联版本检查。当前单据快照仍须存在、记录 `status=CANCELLED`，且采购面料/订购量一致；
仅修改生产/采购单当前状态而没有对应取消快照时仍需人工核对，不能借此绕过旧关联检查。

回归覆盖连续两次后续 STOCK 提交，确认取消单据、内容版本及历史快照未被重写；活动单据的旧关联
仍报错，核验失败仍遵守原有租约、快照复核、退避和人工处理流程。

## 关联缺失能发现到什么程度

| 剩余证据 | 当前检查的结果与边界 |
|---|---|
| 活动单据最新关联丢失，但较旧订单修订关联还在 | 报关联版本落后；不能靠序号证明所有历史记录完整 |
| 部分正数量采购关联丢失，MO 关联仍在 | 材料总量不足通常可检出，不能据此猜测具体缺哪张 PO |
| 生产关联丢失，当前 MTO 行或采购关联仍在 | 生产计划/材料需求差异可检出；仍不自动推定归属 |
| 全部关联丢失，但当前 MTO 行还在 | 正数需求没有生产覆盖，可检出 |
| MTO 当前行与相关全部关联一起消失 | 当前事实检查可能返回空列表；混合订单的 STOCK 部分仍可能完全一致 |
| 零数量单据关联丢失 | 数量核对可能没有变化，不能证明关联存在过 |
| 只有未关联 MO/PO，或只有 PO 的父 MO 外键 | 不能据此认定是哪张订单丢失关联；仓库允许未关联单据/占用补购 ID |

不能把最后三类空结果表述为“关联完整”。`ProductionOrder` 没有独立订单归属，
`PurchaseOrder.production_order_id` 只指向 MO，无法区分从未关联与关联被删除，也不能在同 SKU
的多张订单之间选择归属。本轮没有将所有未关联单据强行归入订单或自动重链。

## 可证明但尚未接入自动核验的来源证据

若 COMMITTED `Operation`、对应 `Plan.normalized_changes.downstream`、订单/修订身份和提交回执
仍完整，计划清单可以证明该次原子提交应写入哪些关联。这种情况不能称为“架构上完全无法判断”。
合成探针中，取消后继续提交 STOCK 改动，再删除仍活动的 MO-2001、PUR-3001 关联和当前 MTO 行，
当前事实检查为空，但该次提交的保留计划明确列出这两条应有关联。

该来源审计仍未加入每次持写锁的全库核验：历史计划/JSON 扫描会改变成本，且须明确定义 seed、
导入、旧回执、取消后不再重链、已被新修订替代的关联，以及证据保留/损坏时的处理规则。
本轮不把仅局部可用的清单当作全库完整归属证明。

建议下一步先做独立只读来源审计，验证计划、操作、修订及预期关联的身份一致性，只输出人工调查项。
若需可靠的自动断链检测，应将版本化的“预期关联/托管来源”清单与业务提交同事务持久化，建立按
订单修订和单据类型/ID 的索引与约束，并为 seed/导入显式登记来源。恢复只能使用可信记录或经批准
的新业务修订，不能按 SKU、数量或 ID 命名规律重建客户归属。全部来源证据同时丢失仍需要外部可信备份。

## 运行边界

无新增数据库列、迁移、配置或自动修复入口。现有租约与结果写事务保持不变；当前快照键合并查询，
不引入逐单读取或历史 JSON 装载。查询次数固定仍不代表内存与持锁时间固定。
回退至 ae1899d 会恢复采购快照漏查与合法取消后重链误报；PR 原有迁移/排空旧核验进程要求仍适用。
已通过的旧操作不自动重查，本轮没有真实浏览器、ERP、自由语言或生产负载验收。
