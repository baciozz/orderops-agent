# 有明确覆盖范围的核验协议

用户已选择明确标注范围的部分核验。该选择取代此前“全库或部分”的待决项；不授权来源推断、
历史数据接纳、自动改写、合并或部署。本轮交付范围契约、实现顺序和可执行合成验证。
**完整生产清单协议及依赖闭包尚未接入。** 后续[执行证据拦截](SCOPED_EXECUTION_GUARD.md)
已拦截有保留证据的本次操作行/关联同时丢失，不代表未知父图、历史闭包和全库盲区均已关闭。
后续第一片已实现 [批准执行字段保留与只读报告](EXECUTION_EVIDENCE.md)：新增实际事务证据和 CLI，
只覆盖单次提交的明确字段，父图和共享闭包仍标为未证明；不接入旧 pending 或自动放行。

先决条件见 [清单设计](LINK_MANIFEST_DESIGN.md) 和 [共通门槛](LINK_MANIFEST_COMMON_GATES.md)。
以下结论不等同于“产品已经具备上线条件”。当前仍为受控单机演示，缺认证/授权和经实际验收的写者隔离。

## 结论必须绑定对象、属性和依赖

请求对象采用精确 typed identity；订单至少绑定 ID、当前修订、完整图清单 ID/digest/协议、
全部引用根及 trust epoch。每个目标分别计算依赖闭包和核验结果，不能先过滤数据库再执行原全库函数。
范围是要证明的命题，例如“订单 A 的修订 3 当前行集、归属图与执行事实相符”；
单次 operation 的边集合审计仍只证明该次操作，不提升为订单来源完整性。

报告应显式保留：

| 字段 | 含义 |
| --- | --- |
| requested | 调用者原请求的所有对象及要验证的命题，未知/不存在的请求不得被过滤 |
| targets | 每目标的精确版本、所检查属性、闭包、证据摘要、结果及稳定原因；有未知父图不能输出对象通过 |
| covered / coverage | 能证明的目标；complete_for_requested、partial_for_requested、none，仅相对于原请求 |
| dependencies | 因库存、单据、来源或历史依赖额外检查的范围外对象；不悄悄加入请求对象计数 |
| outside_request | 清册中未请求的对象；其中部分可能作为依赖被检查 |
| unassessed_objects | 实际没检查的可观察对象及原因，如 OUTSIDE_REQUEST_AND_DEPENDENCIES |
| inventory_basis | 清册来自哪个一致快照；仅 observed_catalog 不能证明被整体删除的历史对象不存在 |
| observation | 读取时刻、数据库实例/世代、协议、结果 ID、必要事实/根版本；“当时观察”不是持续保证 |
| global_completeness | 固定 not_assessed；即使所有可观察对象通过也不变为全库通过 |
| authorizes_business_action | 固定 false；核验报告不代替提交批准或业务授权 |

未覆盖原因区分：来源/父证明缺失、闭包成员未知、实际事实矛盾、协议不支持、上限/运行失败和过期结果。
闭包不完整时，未访问对象标为 NOT_ASSESSED_CLOSURE_INCOMPLETE，不得据此断言它与目标无关。
异常不可合并成空数组或计数零。存在可复现矛盾的目标标为 findings；仅因证据不足的标为 inconclusive；
二者均不进入 covered。合成模型用逐目标 reasons 展示这些情况，不是最终 API schema。
摘要与计数只是索引/完整性校验，详细对象列表不能仅以百分比代替；超限需要显式截断标志和未完成状态。

## 闭包规则与可以保留的部分结论

1. 对每个目标先验证来源根、逐代父授权、回执和批准绑定，再读取该可信图承诺的依赖集合。
   未知父链保持未知，不允许把当前幸存的行/边作为“新的较小完整图”。对未知目标可列观察值，不能列 verified。
2. 并行核对当前事实中的依赖与承诺集合，检测缺失、额外、重复和错归属；双方集合都参与。
   不从 SKU、数量、PO parent MO、命名或 CANCELLED 标签推断归属。单据键包含类型。
3. 对每个 MO/PO 检查全局 claim 和实际所有订单关联；范围外订单的冲突不能被过滤。
   取消保持原归属、取消 operation/修订/快照、授权祖先及旧根；新根不掩盖旧根撤销或锚点缺失。
4. 对共享库存，检查仓库+SKU 的所有贡献者、预占/发货/收货/流水及所需来源证据和真实余额。
   只有集合完整性也能证明，数量加总才有意义；看不到其他贡献者不等于不存在。
   若库存来源根或完整贡献者清单未知，该库存命题以及依赖它的目标不通过。
5. 递归扩展共享依赖直到闭包；循环用已访问 typed identity 处理，父链环仍非法。
   深度/节点/字节/时间上限耗尽，受影响目标为未完成，不能截断后继续宣称通过。
6. 未覆盖的 A 不必污染无依赖关系且已证明的 B。反之 B 若共享 A 的库存或单据，不能通过缩小请求绕过 A。
   若只想报告 B 的独立属性，必须另建明确命题，不能把某一属性通过压缩成“B 已验证”。

例：A 的图和独立库存可证明，历史订单 L 无根且与 A 无关，可报告 A covered、L 未覆盖。
若 L 贡献 A 使用的库存，则 A 的订单完整命题也未完成；独立的 B 仍可 covered。
仅审计 A 的某次 COMMITTED 操作成功，不足以跳过 A 的未知父图或声明库存集合完整。

## 业务提交、重放与结果发布分别处理

这次选择改变未来核验报告的语义，不自动改变旧 `committed_verification_pending` 的含义或提交规则。
第一阶段范围报告仅只读旁路，不能写该布尔值，也不能由部分通过清除原全库核验失败。
现有旧状态必须按旧协议展示；不得把 pending=false 翻译成“来源完整”。

未来 v2 业务提交只要求证明本次批准与实际写入所依赖的闭包，不因一个无关旧订单未知而全库停写；
但真实依赖缺证据时不能授予 v2 有效批准。检查在 BEGIN IMMEDIATE 内重读、比对批准绑定的指针、
父/根状态、trust epoch、锚点、全局归属、成员清单和业务事实；失败则本次业务效果、批准消费、outbox 零新增。
单独的业务状态包括 committed/not_committed/replay，不由 coverage 推导，未知旧数据没有被自动接纳。

已提交键重放保留原 operation 和业务事实，返回原提交与独立核验状态；丢证据不能诱发重执行业务。
清单、完整图转移、取消锚点/claim、批准消费、回执绑定与业务必须同事务写入。恢复只重验，不重建可信证据。

持久结果发布沿用并扩展现有所有权/token/租约与新鲜度围栏：进入写结果事务后重验本次完整闭包及范围声明，
不能仅重验当前订单行，也不能接受旧读快照的成功。最终写前再次检查租约；新接管失败不得被旧线程成功覆盖。
本轮合成模型一律锁内重算，未提出生产性能优化。发布后只保证当时状态；持续失效/调度必须另有可验收机制。

## 迁移和旧 writer 的实施顺序

不自动给旧行生成可信根。人工接纳、共享单据转移、历史删除/checkpoint 和外部导入仍未定义，默认不支持；
若未来确需这些能力，应提交明确的产品/来源授权方案。新创建根也须绑定真实批准和回执，不能只在表中写 TRUSTED。

1. 先完成正式 v2 canonical payload、关系约束和只读解析器；对旧/缺失/损坏/未来协议返回明确 unknown。
   同时为清单、根事件、typed claims、报告对象和核验协议建独立身份与版本。先不改变现有业务行为。
2. 建立可验证的写者清册：API、worker、watchdog、verification、receipt/cut、seed、导入、CLI、恢复、直接 SQLite。
   停止全部旧进程并关闭连接/文件描述符，隔离数据库/WAL/SHM/目录写权限；同身份旧程序不能继续写。
   若部署无法保证这一点，需要受独立身份控制的单写服务，不能以公开 epoch 或启动检查冒充隔离。
3. 停写一致备份后显式结构迁移；旧记录仅登记 observed/legacy_unknown，不补链、不改批准、不重置 pending/重试。
   原始计数、hash、foreign_key_check、约束/索引及 operation 回执须对账。foreign_keys=OFF 的旧连接也必须已隔离。
4. 新进程对新/池复用连接在写事务前检查 schema、writer/protocol epoch、FK 及数据库世代。
   v2 批准、所有实际写路径与结果发布同时切换；不能只升级 kernel 或只换自动 verifier。
   旧批准不能伪造新增依赖字段；进入 v2 时重新规划批准。读旧证据始终保持原协议和 unknown 范围。
5. 小规模合成新订单从创建根到取消/历史/补单/混合库存完成真实协议验收；再做规模锁测量及故障/恢复门禁。
   无外部运行环境隔离证据时只可生成标注为观察的只读报告，不启用能影响业务/旧 pending 的新发布路径。

迁移中途失败须整体回滚结构事务或保持停写恢复一致备份，不能在半迁移库运行旧进程。
迁移成功但尚无新业务时可停写恢复原备份。已有 v2 业务后不能直接恢复切换前备份；保留新库只读，
由支持新证据的兼容版本恢复，或先完整导出对账再决定回退。降级不得将 partial/unknown 转成旧通过。
该运行环境切换属于外部生产部署权限边界，本轮没有执行。

## 本轮交付及验证边界

`tests/scoped_verification_model.py` 仅由测试导入，在每次新建 SQLite 中模拟上述闭包、报告与发布围栏。
它使用 fixture 独立提供的逐节点授权、来源根、依赖成员和事实见证；**当前生产库不具备这些见证**。
测试不会从幸存记录生成见证。它不解析实际 Plan/Approval/receipt，不实施迁移、来源接纳或真实 writer 隔离。
来源模型当前仅支持其合成取消生命周期；实际部分尾单/采购补单/混合库存继续由清单事务探针验证，
不能把这些独立实验当作已经实现完整生产闭包。

运行：`python -m pytest -q tests/test_scoped_verification_design.py tests/test_manifest_common_gates.py tests/test_link_manifest_design.py`。

| 合成验收 | 已覆盖的断言 |
| --- | --- |
| 范围与未知 | 独立旧订单、混合已知/未知请求、空/不存在请求、全部已知对象覆盖仍不宣称全库 |
| 父/根/取消 | 缩小范围不能掩盖父/批准缺失、旧根撤销、取消锚点/claim 损坏；多代根和未来修订沿用共通回归 |
| 共享依赖 | 隐藏或明确的旧库存贡献者污染相关目标；可信范围外贡献者进入闭包且证据变化改变摘要 |
| 全局归属 | claim 正确但范围外事实链接冲突仍拒绝；单据类型、取消归属保留沿用共通实验 |
| 缺失与上限 | 依赖声明/成员证明未知、事实损坏、行与成员同时丢失、额外依赖、闭包限额均不通过 |
| 并发与恢复 | 旧 WAL 成功锁内重算为失败、接管后的新失败不能被旧 token 覆盖、检查中租约过期拒绝发布 |
| 提交前重验 | 独立显式批准后，根 epoch、共享成员、事实或父证据改变均拒绝 marker 写入；检查/写入间竞争连接被写锁阻止，注入中断零效果 |
| 不写业务 | 观察前后数据库 dump 相等；重试不修记录；原件恢复可重验；报告发布不写业务 marker、不含 pending |
| 旧 writer 反例 | 共通测试保留旧 verifier 可越过未来 schema、FK OFF 可越过指针外键、公开 epoch 不能鉴别写者 |
