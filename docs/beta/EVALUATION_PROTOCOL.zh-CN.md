# 正式评测交接：评分候选、隔离与前置条件

2026-11-09。本轮只补评测工具和交接，不修改应用、提示、模型契约或数据v3。新风险保留集**尚未生成、读取或运行**；下面的离线测试只用丢弃式开发夹具。完整G1/G2/G3仍未通过。正式验收继续遵守原方案（私有仓库另存完整快照；私有源码候选只保留本文列出的相关门槛），不以这份准备文档关闭门槛。

## 评分定义先固定，再由真人确认

候选定义见`benchmarks/scoring_policy_v1.json`，SHA256为`5ec512f4a1470c2ac907a2dd6a5571fc87da74f5b5bc316d63b6b7ac90e128cf`。状态为`PENDING_INDEPENDENT_HUMAN_CONFIRMATION`，不是已批准的正式评分标准。变更任何定义都须在推理前重新冻结、记录原因，不能看保留集结果后改评分。

`benchmarks/score_review.py`只做推理结束后的离线诊断，不导入应用、模型客户端或凭据。它先校验并读取已固定的输出，再打开私有参考，输出永远保留`formal_qualified=false`。主协调者另行核对人、数据独立性、完整分母和发布门槛。

| 层次 | 候选判断 | 缺证据时 |
| --- | --- | --- |
| 原始理解 | 订单、处置、动作、原/目标SKU、数量、单位、前后值与允许集合严格一致；动作顺序不计 | 超时、拒绝、格式错误、不必要澄清计失败 |
| 额外零效果动作 | 单列计数；候选主分默认不允许，除非参考事先列入允许变体 | 不能在原始评分前静默滤掉 |
| 规则后结果 | 独立比对状态与每SKU旧/新值 | 规则拦截或过滤不修复原始理解分 |
| 应澄清 | 允许处置正确，真人核对必要事实编码覆盖，不逐字匹配追问措辞 | 未复核为unknown，不当作通过 |
| 来源 | 自动核对行号、原文包含；关键字段是否确有语义支持须真人核对 | 片段存在不等于支持，未复核为unknown |
| 风险 | 分别记录危险原始建议、危险有效清单、实际越权/业务写入 | 没观测为unknown，不能填0 |

真人输出复核须绑定精确`proposal_sha256`；工具接收的`reviewer_kind/owner_verified`只是外部确认的元数据，不能认证真人。AI不得填写为真人；单测里的模拟元数据不是审阅证据。待真人明确确认的重点是额外零效果动作的主分规则、澄清事实集合与危险建议/危险执行边界。规则后清单正确、零业务写入、人工纠正完成分别报告，均不单独等于模型正确。

评分CLI的输入结构可参照`tests/test_evaluation_scoring.py`中的**开发夹具**，不能把夹具当新保留数据。`from_baseline`适配已保存的单次提取记录；真正运行前固定完整尝试索引，每个计划尝试都要有输出或失败占位。当前工具只统计已提供记录，不能证明调用方没有漏交失败；协调者必须将输出ID与冻结索引逐一对账。格式和类别不能事后重分组；所有支持格式每类至少10个保留样本。

```bash
# 仅在隔离评分环境运行；变量是路径/摘要，不是凭据。
.venv/bin/python -m benchmarks.score_review \
  --observations "$OBSERVATIONS_FILE" --observations-sha256 "$SEALED_OUTPUT_SHA" \
  --references "$PRIVATE_REFERENCES_FILE" --policy-sha256 "$FROZEN_POLICY_SHA" \
  --human-assessments "$VERIFIED_ASSESSMENTS_FILE" --output "$NEW_SCORE_REPORT"
```

## 新风险集由另一环境维护

旧30条保留风险已被开发AI读取，继续作已知回归；不能改数字、换ID或换格式后重新称独立。新≥30条风险故事须由独立维护者在开发者和被测模型均不能访问的环境生成与保管，并由真人复核全部新风险及至少20个开发/验证故事。独立性需要真实权限/环境边界，不能用同UID的目录或chmod代替；作者身份、语义新颖性和未提前暴露都不是哈希能证明的。

作者将实际原件放`public_inputs/`，答案、允许结果、必要澄清、禁止动作和来源说明放`private_oracle/`；单个案例用`case_id/story_id/synthetic/input_files/oracle_file`登记。`benchmarks/risk_manifest.template.json`与`risk_approval.template.json`均为空白待填模板，不含新故事或真人签名。作者按[来源与输入限制](INPUT_SUPPORT.zh-CN.md)准备实际可读的基线、需求和映射；不得把答案、渲染底稿、案例ID或评分元数据作为客户附件。

```bash
# 在独立作者环境、仓库外的私有目录运行；不在本开发实例填充实际保留集。
.venv/bin/python -m benchmarks.seal_risks seal \
  --root "$AUTHOR_BUNDLE" --manifest "$AUTHOR_MANIFEST" --output "$NEW_PRIVATE_FREEZE"
# 真人/协调者完成并验证所有门槛后，才释放公开输入；输出目录必须全新。
.venv/bin/python -m benchmarks.seal_risks export-inputs \
  --root "$AUTHOR_BUNDLE" --frozen "$NEW_PRIVATE_FREEZE" \
  --approval "$VERIFIED_APPROVAL" --output "$NEW_RUNNER_PUBLIC_INPUTS"
```

封存输出仅打印数量、数据/评分摘要，不打印文字或标签。完整freeze和approval含私有映射，留在作者/评分方；开发者只收数量、摘要和门槛状态。导出重新核对所有文件哈希，拒绝符号/硬链接、越界路径、答案字节别名、冻结后更改及缺少审批。导出只复制公开文件、改成不含案例名的文件路径；`RUNNER_INDEX.json`是协调元数据，绝不作为模型附件。它不是完整应用导入器，协调者须按确认过的角色/映射导入。工具不判断文件里是否伪装了答案，独立真人仍须检查内容和边界。

正式推理结束后先固定全部输出，再将输出交给另一评分环境与私有参考比对。若基于保留失败调试，相关故事及所有改写转回归，重新补充并冻结，不能挑最好一次。保留集不进开发Git、Library演示包或模型上下文。
