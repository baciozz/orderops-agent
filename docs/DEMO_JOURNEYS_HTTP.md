# 文本风险澄清与 Excel 缺货修正：HTTP/HTML 验收

基线为 PR #61 `e91a661`。全部使用隔离合成 SQLite 和 loopback Uvicorn，
从实际网页表单的字段开始，经 HTTP 上传真实 XLSX、运行 worker、回答、批准、提交、结果读取和同键重放。
浏览器交互权限限制仍保留；这证明 HTTP 与返回 HTML 的业务流程，不能替代文件选择、点击和页面时序的真实浏览器验收。

## 实际发现与修复

1. 文本「C 款黑色 L 全部改藏青」进入 NEEDS_CLARIFICATION，批准被阻止，
   但任务 `/view` 和 HTML 都没有待确认问题。规划器已经保存“已开裁 120 件不能改色、未执行量 180”，
   页面只读取了解析回执，遗漏规划阶段的问题。现在显示当前 DRAFT 的问题；
   新答案入队使旧计划失效后，不继续展示旧问题。批准、提交和风险判断本身没有放宽。
2. Excel 表格白 M 30、蓝 L 25 导入后出现蓝 L 缺 5，页面回答框却提示「只改未开裁」。
   实际照提示回答会占用最后一次 worker 尝试，随后再提交正确的「蓝 L 改成 20」会耗尽预算而失败。
   现在首次导入的回答提示是「按附件新建订单」，有候选或缺货历史后提示「蓝 L 改成 20」，
   并说明第一次须勾选表格、修正可继承原来源。处理次数、有限语法、来源证明和审批规则均保留。

提示只是帮助输入，不自动填写或发送答案、不自动选择来源、不自动调用 worker 或授予批准。
数量例子仍是有限语法示例，用户须结合当前缺货问题、唯一匹配行和可用库存核对。

## 已执行的用户流程

| 流程 | 实际验证 |
| --- | --- |
| 文本风险 | 表单入队 → worker → 显示 120/180 的澄清问题 → 回答只改未开裁 → 再次 worker → 审批 → 提交 |
| 过时页面 | 回答后重送旧 fence 的不同请求得到 409，数据库不变；新答案入队后旧问题不再充当当前问题 |
| Excel 异常恢复 | 上传损坏 XLSX 被安全拒绝，再上传原始合成表；没有消耗额外 worker 尝试或建立业务订单 |
| Excel 缺货 | 从 HTML 读取首次回答提示并选择来源 → 缺 5 且不能批准 → 从 HTML 读取修正提示，以空来源集合继承原证据 → 第三次 worker 得到白30/蓝20完整计划 |
| 人工边界 | 批准后 Operation 数量仍不增加；单独提交才生成业务结果，原表25与修正20的来源分别显示 |
| 提交结果 | partial，整单图 inconclusive、全库 not_assessed；同键重放返回同一 operation，数据库 dump 不变 |

回归入口：`python -m pytest tests/test_demo_clarification_journeys.py`。
这两项新测试在基线失败，修复后与既有表格、任务视图和演示测试共同通过。

本片无迁移、请求字段或核验语义变更，不重置预算、不修复业务数据。
仍须单独运行 worker、人工核对并批准、再提交；预算已耗尽的旧任务须按既有规则新建任务重新上传。
父链、完整历史和共享依赖闭包未实现，有限字段一致不能作为整单或全库通过。
本轮没有真实客户数据、ERP、付费模型、合并、部署或 PR 正文重试。
