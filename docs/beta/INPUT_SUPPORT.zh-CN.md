# 本机输入支持与来源确认

这是开发预览的文件读取与人工确认边界。真实模型理解、完整保留集指标与独立用户验收仍未通过，不能因文件成功打开就宣称订单已理解或执行。

| 输入 | 基本读取 | 重要边界 |
| --- | --- | --- |
| 中文文字/多轮聊天 | UTF-8原文行，保留发言人、时间、引用、撤回文字 | 语义由真实模型提取；目前没有自由语言通过率。不要机械采用最后一句。 |
| 粘贴表格/Markdown | 制表符或单个Markdown表格预览、列映射，保留周围备注 | 无关键列时需人工补充或转录；不会把“数量”自动解释为加量或最终总量。 |
| CSV | UTF-8/BOM，或显式选择GB18030；RFC引号、逗号、换行与前导零 | 不猜编码。字段按文本读取；数量映射须为明确整数。导出沿用公式注入防护。 |
| XLSX | 逐行SKU、尺码横排、颜色尺码矩阵；多工作表选择、合并范围明确展开 | 隐藏行仍读取并标记；公式、宏、外链整文件拒绝，不使用公式缓存或补零。非通用Excel布局推断器。 |
| 文本层PDF | 每页文字与页码，换行/重复表头原样保留 | 不伪造字段坐标；需对照原页。无文字页会阻断自动采用，扫描PDF请改传PNG/JPEG或明确人工转录。 |
| PNG/JPEG | 本机Tesseract实际读像素，EXIF校正与0/90/180/270度旋转；显示预览、区域与OCR分数，另做有界尺码字符差异、低分中文和数字提示 | 分数不是正确率；编号、款色码、数量、金额、日期及漏读内容必须对照原图。尺码冲突、低分数字或检查不可用时先完整转录；低分中文须逐一确认。原OCR保留，不能识别截断图片之外的上下文。 |

基本角色：订单基线、可用现货库存、已发/已裁总量、生产采购关联、客户要求。默认“尚未确定”，不会按数字或文件名猜角色。订单号须人工从候选明确选择，不能把多单匹配静默改绑。订单基线和客户文件分开确认。

表格先选工作表、表头行、布局和列映射。原件没有SKU时，可由明确的款号/颜色/尺码三元组生成稳定内部键；这是标识规范化，不是推断订单或单据归属，颜色别名不会自动合并。未填写已发、已裁、可用库存保持未知；缺版本或履约方式须明确人工补充。人工常量和转录有独立来源标记。重复行、冲突版本和互相矛盾的履约总量拒绝，不擅自汇总历史事件。

客户要求可以来自多个已确认原件。完全相同上传返回原件；同上传标识换内容拒绝。同名不同内容保留两份，须说明关系或明确排除，不把最新文件名当作事实优先级。新增、转录、角色/映射或基线更新会使旧提案和确认失效；排除对象及原因仍属于未覆盖范围。源文件哈希不符时提取、确认和导出会阻断；恢复只接受相同大小/哈希原件，不静默替换新内容。

## 上限和运行环境

每任务最多6份原件，每份5 MiB；表格1000行、64列、20000单元格，提取文字60000字符；PDF最多20页；图像单帧、800万像素、最长边6000像素。超限整份拒绝，未截断后继续。模型开发入口另限序列化提示的20000保守token上界、输出最多3000token，可能比读取上限更小；超出时提示拆分或人工处理，不删关键资料。

本轮实际验证Linux/Python3.12、桌面Chromium，其他操作系统与浏览器尚未验收。读取在无模型凭据的独立Python子进程中进行，并设55秒墙钟、CPU/内存/输出限制；这些限制不是任意恶意文件的安全沙箱保证。PDF/工作簿中的代码、链接、宏、公式不执行。XLS、XLSM、语音不支持；请提供静态XLSX、CSV、文字或图片。

## 中文OCR首次准备

本机需有Tesseract可执行文件。当前云镜像已有5.5.0，但没有中文语言数据；没有系统安装helper，因此使用官方固定版本语言数据存入用户目录，不修改系统配置。下载不是模型能力评测。开发检查使用合成图片及去标识的公开实拍收据裁切，后者不是中文服装业务验收。

```bash
mkdir -p data
.venv/bin/python scripts/prepare_ocr.py --directory "$PWD/data/ocr"
export OOS_OCR_DATA_DIR="$PWD/data/ocr"
```

脚本默认从官方`tesseract-ocr/tessdata_fast`固定提交下载chi_sim/eng和许可证，校验预置SHA256；不覆盖不符文件、不发送客户资料。语言权重不提交仓库或发布候选包，首次下载与五分钟演示分开计时。主文字仍固定使用chi_sim配置并记录组件版本；另一遍chi_sim+eng只检查同一坐标内尺寸相近字符是否有不同候选，绝不拼接或替换主结果，也不把候选直接交给模型。候选或主结果都可能有误。

也可选择官方较大、通常较慢的 `tessdata_best` 中文及英文数据（约42 MB），保存在**另一新目录**中：

```bash
.venv/bin/python scripts/prepare_ocr.py --directory "$PWD/data/ocr-best" --profile best
export OOS_OCR_DATA_DIR="$PWD/data/ocr-best"
```

两个配置均从官方固定提交下载并核对文件哈希；任何已有文件不匹配时拒绝覆盖，不能在同一目录混用两套数据。预览会记录明确配置目录中可读取语言数据的 SHA-256；无法确定时不猜版本。高精度数据对某些图片可能更好，对其他图片仍可能错，且耗时更长；不得把置信度、数据配置或无提示当成正确率。

这只检查有限的尺码字母、带明确尺码标签的候选和部分低分易混淆字符；低分字母数字混排词也提示核对，可能误拦低分款号或订单号。即使两遍读成同一个低分歧义字，也会提示核对，但两遍相同而高分读错、尺寸未被识别或其他字段错误仍可能漏掉。阈值只用于触发核对，不是正确率。没有提示不代表正确，仍须逐项对照原图。若存在冲突或低分歧义，或eng缺失、第二遍超时/失败、坐标或规模无法安全核对，必须先在原件页面完整转录并说明原因，确认后才可采用；原OCR及预览保留，新文字标记为人工转录。

中文词分数低于50时，来源页列出最多25个需核对区域，并要求单独确认已逐一对照原图；发现错误或无法判断时须先完整转录，不会自动猜色或替换文字。超出25处仍需核对完整原图；若低分中文检查不可用则必须转录。

含数字的OCR词分数低于80时，来源页列出最多25个区域并要求对照原图完整转录后才能确认；检查不可用时同样须转录。它也可能拦到正确的订单号或款号，且漏掉被错读成字母、完全未读出或高分错误的数字，不是数值正确率。所有直接采用图片OCR的情况，不论有无提示，都必须单独声明已核对原图中全部编号、数量、金额、日期及漏读内容；发现错误或不确定时先完整转录。勾选是用户声明，不证明真人身份或正确性。

旧图片没有数字检查记录时不能静默沿用旧OCR：历史确认、原件和提案保留，但再次生成、核对或导出时会要求返回来源复核。相同文件在同一任务重传会复用旧结果，不会重读；请新建任务重新读取，或在旧任务对照原图完整转录并重新确认。已转录的文字单独标为人工来源，不能当成自动识别成绩。

已实测：初始chi_sim+eng组合把清晰图中的“藏蓝”误识为拉丁字符，失败保留；改用chi_sim后该开发样本正确，但这不是图片准确率。实际OCR测试需明确配置：

```bash
.venv/bin/python -m pytest tests/test_review_documents.py tests/test_review_sources.py \
  --ocr-data-dir="$PWD/data/ocr"
```

CI没有中文数据时明确跳过真实OCR专项，不用Mock冒充通过；文字/表格/PDF和安全边界照常回归。页面会提示缺少语言数据，不拿英文OCR猜中文。

## 本地保存

新清单原件默认保存在SQLite数据库旁的`review-originals`，目录0700、原件0600；也可沿用显式`OOS_SOURCE_STORAGE_DIR`私有目录。工作区只存来源元数据、提取、映射、人工纠正与版本，不生成业务Plan/Approval/Operation。普通API不回显存储物理路径。没有自动删除；失败事务可能留下未引用的私有文件，后续清理必须先核对备份与引用，不把未知文件直接删除。

来源证明只针对实际采用的原件、字段和行/页/区域；未证明ERP当前事实、完整父链或共享依赖，默认只导出处理建议。确认清单不等于批准或执行订单。人工纠正不能当成模型识别成绩。

## 从数字复核候选回退（SQLite）

本节仅针对回退到紧邻的 `3d4bcd6e555962b287cba70dba719873a2db6084` 版本，其他版本和数据库未验证。旧版不具备数字复核门槛，回退期间必须人工对照原图，不能认为该门槛仍然有效。

1. 先停止应用写入，并分别备份 SQLite 数据库（含其一致性所需的 WAL）和原件目录，确认备份可读；保留一份不变的原始备份。不要在运行中的数据库文件上直接复制并覆盖。
2. 在当前版本所在的受控环境，建立仅自己可访问的新目录。工具先只读复制已停写的数据库和存在的 WAL 到私有临时目录，再用 SQLite 备份 API 从该快照生成新库；检测到复制期间源文件变化或存在回滚 journal 时拒绝，后者须先创建干净的离线备份。原件与图片预览也会复制并校验。下面的路径是示例，请替换为实际绝对路径：

   ```bash
   mkdir -m 700 /path/to/private-rollback
   mkdir -m 700 /path/to/private-rollback/originals
   .venv/bin/python scripts/prepare_numeric_rollback_copy.py \
     /path/to/stopped-source.sqlite /path/to/private-rollback/rollback.sqlite \
     --copy-originals-to /path/to/private-rollback/originals
   ```

   工具不会改源文件或覆盖目标。它将较早数字复核候选写入严格文档结构的三个字段移出，保留 OCR 原文和历史确认；每次回退都追加本轮之前的图片数字复核声明并在副本中将其清除，避免以后升级时沿用旧版无法维护的声明。旧版本留下的单条回退记录会原样保留为历史中的第一条。工具在创建目标前检查全部资料与回退记录，逐份校验原件与预览的大小和哈希，并在私有临时空间中准备副本；原件只复制到空目录，数据库最后生成。不切换部署、不执行订单。普通的校验、暂存和发布错误会清理本次创建的文件，不删除或覆盖已有目标。

   若进程被强制终止、系统断电或文件系统拒绝清理，仍可能留下临时文件或不完整的输出；只有工具明确报告成功后才可使用。发生此类中断或提示清理不完整时，请检查目录并由操作者处理本次残留，勿将它们当成完整备份。源备份和既有文件始终单独保留。
3. 在隔离环境指定旧版使用副本数据库，并将 `OOS_SOURCE_STORAGE_DIR` 指向副本原件目录以存放后续新文件；核对任务、原件、图片预览、历史确认及必要的 CSV/XLSX 导出，再由操作者决定是否切换。历史原件引用为绝对路径，仅修改该变量不会迁移它们，须使用上面的复制选项或采用已核验的原路径恢复方案。副本和原件目录均含可能敏感的业务数据，须按原有私有权限保护。
4. 将副本重新交给数字复核候选时，直接采用图片 OCR 的资料须按页面提示重新对照原图、确认或完整转录；历史声明仍保留供审计，不代表已完成重新复核。已有完整转录仍标为人工来源，须由人自行对照原图。普通文本资料不因此增加图片数字勾选。不要用回退前的旧备份覆盖回退期间产生的工作；先保留两份数据并核对差异。由旧版新增的图片没有数字检查信息，也须重新读取或转录。

回退转换只验证本机 SQLite 中资料清单的兼容性；它不保证旧版具备新增防护，也不替代针对其他外部存储、业务写入和部署环境的备份与恢复演练。
