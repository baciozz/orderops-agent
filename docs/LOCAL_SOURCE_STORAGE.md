# 本地原件保存与恢复

表格订单依赖原始文件，而不只依赖已保存的提取片段。之前上传仅写临时目录，清理后审批/提交会安全拒绝，但影响连续本机试用。现在可显式配置持久目录；仅用于当前受控单机、同一操作系统用户的合成数据演示，不增加认证、第三方服务或生产部署能力。

## 启用与安装

为每个数据库使用独立的原件目录，不同数据库不要共享目录。在 API 启动环境中设置 `OOS_SOURCE_STORAGE_DIR` 为专用绝对路径。例如在源码根目录完成 `make init-db` 后：

```bash
export OOS_SOURCE_STORAGE_DIR="$PWD/data/sources"
make run
```

普通 wheel 安装也读取同一环境变量，可用 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`。隔离演示命令使用 `env -i`，须在该命令中明确传入变量；只在外层 export 不会进入被清空的环境。新用户演示指南已使用 `$DEMO/originals`。

- 父目录须已存在；程序只创建末级目录，模式 0700。已有末级目录必须属于运行进程用户且模式为 0700；不替操作者 chmod，不接受路径或祖先中的符号链接、相对路径、`..` 或根目录。
- 原件使用服务器生成的 `SRC-*` 名称，独占创建、模式 0600，不使用上传文件名拼接路径。写入内容和目录均 fsync 后，数据库事务才可保存成功回执。需要支持这些 Linux 本地文件操作的文件系统；不提供跨机器或网络文件系统保证。
- 不设置或留空时保留临时目录行为。默认和持久模式的新文件均使用私有权限。API 重启不删除原件；目录位置、可用空间和外部清理仍由操作者管理。
- 不安全目录会使启动明确失败，日志仅给出 `SOURCE_STORAGE_UNAVAILABLE` 等结构化错误码。运行中写目录不可用返回 503 `SOURCE_STORAGE_UNAVAILABLE`；修复权限/空间后使用原上传键重试，不能靠静默切换到临时目录掩盖失败。

配置路径属于操作者可信配置；运行期间应停止移动、替换或开放目录权限。此实现不防御同一 OS 用户/管理员恶意替换目录，不代表有多租户文件隔离。

## 重启、重放和缺失恢复

数据库继续记录每个来源的绝对路径、大小、SHA-256 和任务归属；没有数据库迁移或路径重写。重启后按该记录读取，不通过当前配置目录或相同文件名猜测旧原件。

同任务、同上传键、同文件名和相同字节的重放会验证原件为普通非符号链接文件，大小和摘要一致后返回原 `source_id`；不会重新写入、替换、增加来源或消费上传槽位。双进程竞争同一上传键仍由现有数据库回执事务去重。

原件缺失或变化时，上传重放返回 409 `SOURCE_UNAVAILABLE`，表格审批/提交返回 409 `SHEET_CONTEXT_INVALID`。已保存提取片段仍可读，但不证明原件可用，也不能替代原件授权。页面保留此提示及新建表格任务入口。

操作者可在停写并核对任务后，用可信、字节完全相同的备份恢复到数据库原先记录的位置，保持文件 0600、目录 0700，再以原上传键核对。不要从当前片段重造 XLSX、修改数据库摘要/路径、用同名文件覆盖或通过重新上传“修补”既有回执。

- 批准前恢复，原上传键可返回原来源，核对后仍须显式批准。
- 因缺文件提交被拒后，旧批准保持失效，文件恢复不会自动重新授权。按既有提示取消尚未提交任务，再新建任务、重新上传和核对、批准后提交。
- 已经提交的操作，即使文件后来丢失，原提交键仍返回原提交回执，不再执行一次订单。先核对 `operation_id`，不能因来源缺失重提已生效业务。

## 旧任务、切换和回退

启用、更改或取消配置仅影响后续新上传。已有临时来源仍指向原临时路径；不会扫描新目录中的同名文件、迁移来源或认证旧数据。旧临时目录仍须保留或从可信备份恢复原位置。无法恢复时使用明确的新任务流程，不能把持久目录配置当成历史来源恢复。

回退代码不删除数据库记录或文件，已有绝对路径仍可读取；但旧版忽略此设置，新的上传会重新使用临时目录，且不保证新文件的私有权限/同步策略。回退前停止所有 API/worker，保留数据库和所有原件，不删除持久目录或回退业务修订。

## 保留、备份和清理

**本次不引入定期删除、TTL、保留天数、自动整理或备份服务。** 待审批、已提交、已取消任务的来源都可能需要重放或历史核对，不能仅按任务结束状态删除。清空演示数据库也不自动删除原件。

本地备份须先停止全部写者，在同一停写窗口备份 SQLite 数据库（妥善处理 WAL）以及所有 `input_source.storage_ref` 引用的原件，包含旧临时路径，保持受限权限并核对大小/摘要。`audit` 导出不包含原件，复制当前持久目录不能覆盖库内全部历史来源。恢复时保留原路径；更换机器/目录的自动迁移本次未实现。

单持久目录的可信合成库可按[本机离线备份与恢复演练](OFFLINE_BACKUP_RESTORE.zh-CN.md)执行具体命令。该流程可将数据库恢复到新的运行目录，原件仍须恢复到原绝对路径；直接把全部文件搬到新的根目录不受支持。

只有在停写、备份并确认没有任何数据库来源引用的文件，才由操作者人工评估清理；也不要直接信任文件名、修改时间或单一当前任务列表。进程在数据库提交前崩溃可能留下无回执孤立文件，本实现保留它而不覆盖或自动删除。数据保留期限、外部备份、加密与真实敏感数据政策仍需另行决定；本次没有选择外部存储，也没有接入真实数据。

## 实际验收

`tests/test_persistent_source_http.py` 启动真实 Uvicorn：上传表格、生成计划，停止服务并清理其独立临时目录，再启动并批准/提交；另一个独立服务进程同时重放同一上传键。核对原件、来源回执、订单、库存和提交身份，没有重复写入。也覆盖原件缺失/变化拒绝、可信恢复和旧临时任务不被新目录重新绑定。

`tests/test_source_storage.py` 使用真实文件系统验证 0700/0600、拒绝公开/符号链接目录与同名覆盖、持久写入同步失败的数据库回滚和原键恢复。现有上传回归继续覆盖独立进程崩溃、事务后丢响应、并发去重与证据保留。

这不是断电/硬件故障证明、浏览器交互验收或生产就绪认证；提交后核验仍只报告限定范围 `partial`。
