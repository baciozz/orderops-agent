2026-11-11 授权总额改为 $30，代码随之调整；本项实现与测试全部离线（MockTransport），真实请求 0 次、账本 0 美元。

- **金额上限**：`app/config.py` 的 `HARD_BUDGET_CEILING_USD` 为 **30.00**，`OOS_LIVE_BUDGET_USD` 默认仍为 5.00（30.00 只是代码硬上限，忘设预算时不会越过 $25 停止线）；有效上限取 `min(OOS_LIVE_BUDGET_USD, 30.00)`，各阶段累计上限须在运行时显式设置。按 v2 总则，真实评测运行时应显式设 `OOS_LIVE_BUDGET_USD=25`，$25–30 为缓冲不主动使用。`check-model-auth --probe` 的累计上限跟随有效上限（`OOS_LIVE_BUDGET_USD`），与评测共用同一个持久账本。
- **总调用次数**：常量 `HARD_MAX_TOTAL_CALLS=3000`，在 `BudgetLedger.reserve` 的同一 SQLite 写事务里强制：账本已有 3000 行（含预留、已结算、孤立预留）时第 3001 次直接拒绝（`CALL_LIMIT`），不发请求。调用方传入更大的上限也会被压到 3000；未传时同样是 3000。单次提示 20,000 token 保守上界、单次最多 3,000 输出 token、自动重试 0 均不变。
- **按模型定价**：新增 `OOS_MODEL_PRICES`，值为 JSON 对象，键是模型 ID，值含标准输入/输出美元单价（每百万 token），建议用字符串避免浮点：

  ```
  OOS_MODEL_PRICES='{"<模型ID>": {"in_per_mtok": "<输入单价>", "out_per_mtok": "<输出单价>"}}'
  ```

  未采用 `OOS_PRICE_IN_PER_MTOK__<模型ID>` 形式，因为 `gpt-6.1-sol` 这类 ID 含 `.`、`-`，不是合法的 shell 变量名。字段只允许 `in_per_mtok`、`out_per_mtok`，须为非负十进制数；JSON 无法解析、缺字段、负数或多余字段时配置加载失败。
- **旧变量兼容**：`OOS_PRICE_IN_PER_MTOK` / `OOS_PRICE_OUT_PER_MTOK` 仍有效，但只作为当前 `OOS_LLM_MODEL` 的单价，不会套用到其他模型。若当前模型同时出现在 `OOS_MODEL_PRICES` 且两处单价不同，配置加载失败（拒绝而不是挑一个）。
- **未定价模型一律拒绝**：真实入口（工作台复核、dispatch、`check-model-auth --probe`）都用 `BudgetLedger.from_settings` 建账本，账本只认已定价模型；其他模型在预留阶段抛 `PRICES_NOT_CONFIGURED`，不写账本、不发请求。当前模型未定价时 `resolve_mode` 也报 `PRICES_NOT_CONFIGURED`，LIVE 不启动。每行用量记录该模型自己的单价，预留和结算都按此价实时记账。
- **价格来源**：代码和默认配置里**没有任何模型的单价**，包括强模型 `gpt-6.1-sol`。价格须由操作者按 OpenAI 官方模型页/定价页在调用当天核对后填写到运行时配置，不得凭记忆或旧文档填写；查不到官方价格就不配，该模型即被拒绝调用。
- **零调用自检**：`env -u OOS_LLM_API_KEY OOS_LIVE_ENABLED=false python -m app.cli check-model-auth` 只逐项输出有/无，新增 `OOS_MODEL_PRICES` 是否配置和「当前模型单价」是否可得两行，不发请求、不打开账本。

## S2 / 2A：认证诊断入口（仅离线实现）

本阶段只实现认证诊断与 MockTransport 回归，不运行真实模型评测。当前任务无运行时密钥，真实请求次数和 API 消耗均为 0；2B 须在 2A 审核合并后单独开始。以下历史预算与进度不构成本次新增付费授权。

运行 `python -m app.cli check-model-auth` 只检查进程环境，忽略 `.env` 与缓存配置，不打开 HTTP 客户端或数据库。逐项输出 `有/无/合法/不合法`：LIVE 是否启用、provider 是否为官方 OpenAI、model 是否存在、base URL 是否为官方 `https://api.openai.com/v1`、输入与输出单价是否配置、项目密钥是否存在。不输出配置值或长度，也不验证密钥内容。未显式设置 base URL 时沿用官方默认地址。只存在 `OPENAI_API_KEY` 时只判断其存在，并提示「项目只读 OOS_LLM_API_KEY，请在运行时把同一密钥映射到该变量名」；命令不复制密钥，也不把该变量当作凭据后备。

只有显式添加 `--probe` 才允许一次认证请求，自动重试为 0。执行前由操作者确认 `OOS_DATABASE_URL` 指向本轮共用的持久 SQLite 账本及累计上限；命令要求显式设置此变量，拒绝内存库、SQLite URI 和非 SQLite 地址，不创建临时账本。累计上限即有效预算 `min(OOS_LIVE_BUDGET_USD, 30.00)`，与评测共用同一账本：已有预留、已结算和孤立预留都占用累计费用，达到上限或本次预留将超限即拒绝发送；若提供方回报费用导致累计超过该上限，则报告 `BUDGET_EXCEEDED` 并立即停止。不得通过换库绕过累计限额。

probe 只向官方 Responses 端点发送固定合成提示「回复 ok」，`max_output_tokens=16`、`reasoning.effort=none`、`store=false`，不带业务数据或工具。发送前经现有 `BudgetLedger.reserve` 持久预留，结束后结算同一行；缺少可信 usage 的成功响应、超时和传输错误保留悲观费用。客户端使用运行时代理与 CA，保持 TLS 验证且不跟随重定向。只有模型客户端解封项目密钥用于 Authorization。

probe 的 stdout 为一个 JSON 对象，本地逐项检查输出到 stderr，便于分别采集。JSON 固定含 `status`、`http_status`、`error_type`、`error_code`、`ledger_spent_usd`；未取得的字段为 `null`，费用为十进制字符串。`status=ok` 仅证明本次 HTTP 访问成功，不代表模型内容质量或业务评测通过。401/403 报 `MODEL_AUTH` 并附中文下一步：检查密钥是否被撤销、项目/组织权限、变量名是否为 `OOS_LLM_API_KEY`、网络是否放行 `api.openai.com:443`。429 报 `MODEL_RATE_LIMIT`，其他 HTTP 失败沿用适配器的 `MODEL_HTTP` / `MODEL_UPSTREAM` 等错误码。不反射上游正文、响应头、模型输出、异常文本、traceback 或 Settings 校验详情。probe 失败退出码为 2，成功为 0；默认本地检查退出码为 0，配置无法解析时只报 `AUTH_CONFIGURATION` 并退出 2。

## 强制停止与计量边界

现有 `BudgetLedger` 在发送前通过SQLite写事务保留上界费用和调用槽；失败/超时保留悲观费用，重启不释放。客户端每次设置最大输出token，不启用工具，不自动重试。新工作区也在事务内限制每任务尝试数；同调用标识不会再次发送。账本只能约束共享它的调用，**换新数据库不自动继承累计预算**，因此真实评测禁止每个样本重建费用库或并行使用未计入本轮的脚本。

新入口已实现同一账本总调用上限（v2 起为账本层面统一 3000 次，见上文 S2A 第 4 项）、模型实际序列化提示的20,000保守token上界和最多3000输出token，超限在领取尝试前拒绝；总调用上限有双账本并发回归。完整批量评测器、轮次归档与聚合报告仍待实现，未准备好前不运行大批付费评测。模型调用账本按配置单价和提供方token用量计算，尚未细分缓存写入或账单抵扣，不等于OpenAI最终账单。须报告估计值、未知费用和实际可核实用量。提供方若超出请求上限计费、价格变化、外部进程另用同一密钥或账户的其他消费，不由本地账本控制；保留余量并及时停止，不能宣传对整个OpenAI账户的硬性封顶（v2 本地上限 $30）。项目预算告警也不能冒充提供方硬配额。
