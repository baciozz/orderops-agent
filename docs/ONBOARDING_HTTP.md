## 实际订单演示与恢复

使用真实 loopback HTTP 请求，读取页面字段和返回 HTML；没有浏览器操作或模型调用。

| 阶段 | 实际结果 |
| --- | --- |
| 固定表格入口 | 入队后停止服务，以 Ctrl+C 对应的 SIGINT 正常退出 |
| 排队恢复 | 同一 Python、DEMO、数据库和环境重新启动；原任务仍为 QUEUED，数据库 dump 不变，可继续 worker |
| 上传原表 | 实际 XLSX 含白 M 30、蓝 L 25；上传解析成功，首次回答选择其来源 |
| 缺货处理 | 第二次 worker 显示蓝 L 缺5且不可批准；回答蓝 L 改成20，第三次 worker 得到白30/蓝20完整计划 |
| 人工审批 | 批准后 operation 仍为0，单独提交后才生成新订单 revision 1 |
| 有限核验 | 结果为 partial；整单图 inconclusive、全库 not_assessed，不自动认证父链或共享依赖 |
| 结果证据 | CSV、XLSX 导出与任务审计可读；一个 operation、一份执行证据，model_usage 为0 |
| 提交后恢复 | 再次停止并按相同命令重启，订单行、任务与 operation 身份相同；数据库 dump 不变 |
| 原键重放 | 重启后仍返回原 operation，数据库 dump 不变，没有重复订单或预占 |

短期同目录重启后，已上传原件在这次实验中仍存在；这不扩展临时文件保留承诺，不保证外部清理、迁移或长期重启后的原件可用。
本轮没有通过重新 seed 或替换文件来恢复；也没有重置尝试预算或重新提交新业务。
