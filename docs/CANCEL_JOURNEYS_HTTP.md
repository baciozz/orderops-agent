# 取消、迟到响应与提交竞争的 HTTP 验收

复现基线：PR #61 `51ca65e84db5f67149fa0e7e68983d62c70c3bf7`。全部为隔离合成库、真实本机 Uvicorn HTTP 和本机静态提供方；`LIVE` 只是应用运行路径，未连接真实模型或 ERP，也未操作浏览器。

## 实际执行与结果

| 场景 | 实际结果 |
| --- | --- |
| 处理中取消、再放行提供方响应 | 提供方收到请求后被测试事件阻塞；HTTP 读到 RUNNING，再取消成功，然后放行有效 JSON。任务保持 CANCELLED，无计划、批准、operation 或业务变更；迟到写回被 STALE_ATTEMPT 拒绝。已发送的一次模拟调用仍结算用量。 |
| 已批准，取消先完成 | 取消返回 CANCELLED；原批准提交409 / CANCELLED，业务不生效，没有 operation。 |
| 已批准，提交先完成 | 提交200并生成一个 operation；取消返回 ALREADY_COMMITTED，任务保持 SUCCEEDED，不撤销已生效业务。 |
| 两个独立客户端同时取消/提交 | 使用客户端 barrier 同时发出请求；每次只得到上述一种最终结果。运行包含三次并发观察及后续参数化回归，两类顺序边界另外明确执行；不把请求同时开始当作同一数据库时刻。 |
| API 重启、原输入和取消/提交重放 | 同一库、相同配置重启后返回原任务和最终状态。后台不再调用提供方；取消胜出时原批准仍不能提交，提交胜出时原键返回同一个 operation。重放数据库 dump 不变，无重复订单或库存变动。 |

每个隔离场景只有一次提供方请求；业务数量、订单修订、预占/释放、生产采购事实分别核对。取消胜出为零业务操作，提交胜出为一个 operation/一份执行证据，核验仍为 partial。基线数据库完整性和外键检查通过；原始[观察记录](evidence/cancel-journeys-20261106.json)给出具体结果与证据位置。

持久任务通过独立子进程调用现有后端 `run_once`。迟到响应触发 STALE_ATTEMPT 时，该隔离进程非零结束，任务状态未被覆盖成 FAILED；本轮验证的是取消后的状态与写入保护，未新增公开 LIVE worker 或验收生产调度器。网页/CLI 演示 worker 继续只处理 FIXTURE。

## 复现并修复的 P2 审批缺口与页面说明

补充直接调用批准 API 后发现：已取消的改单任务仍能首次创建批准、返回尚有效的原批准，或在批准实际过期后创建新批准，三种情况均返回200 / ACTIVE。原提交检查仍拒绝已取消任务，没有业务生效，但调用方会得到“批准成功”却无法继续；创建及续期路径还写入了不应产生的批准。

现在 `approve_plan` 在现有 BEGIN IMMEDIATE 事务内、读取/返回有效批准或创建新批准之前检查任务取消状态，返回409 / CANCELLED，拒绝时数据库不变。新单原有的当前意图/取消检查保留原语义，不改历史批准记录，也不恢复已取消任务。

基线取消成功、重启或迟到响应后，页面只有英文 CANCELLED 状态及“当前状态不可回答或上传”，没有明确解释取消已生效、旧批准不能使用，以及取消不保证已发出的模型请求停止或不产生用量。

现在取消页明确显示“任务已取消”，解释不会继续规划/批准/提交，重启、刷新或原输入重放不会恢复任务；LIVE 页面说明迟到响应与可能已有用量。需要继续业务时，先核对当前订单和最近任务，再通过原入口明确新建任务，重新核对与审批。提交先完成时沿用原有“未取消，请刷新查看结果”的交互提示和已提交结果。

本轮收紧取消后批准 API 并新增取消页说明；没有修改取消/提交事务、租约、用量结算、幂等、运行模式或数据库结构，不新增迁移。旧记录不自动回填；回退代码会重新暴露取消后仍可批准的问题，原提交取消检查仍是必要保护。

## 可重复验证与边界

```sh
python -m pytest -q tests/test_cancel_journeys.py
```

7条参数化旅程覆盖迟到响应、取消先、提交先、同时请求和取消后首次批准/有效批准重放/过期续批。4条完整旅程均验证重启与重放；直接批准拒绝还比较整个数据库 dump。页面回归在基线为3失败/1通过，直接批准3条在基线均因200 / ACTIVE失败；独立的6场景运行已验证取消与提交的业务结果。修复后联跑既有批准恢复、共享库存竞争、新单意图及页面回归；完整门禁与精确提交见交付记录。

这不证明真实浏览器点击时序、真实模型停止/计费、多人权限、网络中断/硬件断电、ERP 撤销或生产并发能力。实际浏览器仍未验收；没有合并、部署或编辑 PR 正文。
