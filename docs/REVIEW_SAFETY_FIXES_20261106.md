同一所有者尚未过期、但读取后发生业务写入的情况也被拒绝，测试通过独立 Engine 注入
跨连接提交，并验证修复后恢复。新鲜度采用同一物理连接的 SQLite `data_version`；
读事务不占写锁，租约过期仍能接管，写结果时才获取 `BEGIN IMMEDIATE`。
不会把不同连接的版本值互相比较，详见 [SQLite 官方说明](https://sqlite.org/pragma.html#pragma_data_version)。
租约恰好到期即失去所有权，即使没有新线程接管，也不能清 pending 或修改退避。
同时修正领取租约的时钟位置：SQLAlchemy 延迟发出 BEGIN，时钟须在首次 SELECT 实际获得
写锁后读取；SQL 事件注入覆盖领取与结果写事务的锁等待。既有慢批次测试仍验证租约内
从完成时刻计算退避，成功后进程退出、旧失败不能撤销新成功、worker-loop、幂等回放、
人工核验、日志及并发合法修订路径继续保留。

此轮不新增迁移或公共字段，沿用既有 operation 核验列。升级应先停止并排空旧核验进程，
混跑旧代码不能获得新的结果保护。回退代码会重新引入这两个缺口；PR 整体仍包含下面的
`sync_dispatch_receipts` 迁移及其降级限制。任意并发 SQLite 提交都可能让快照失效，
包括无关写入；这会保守地增加重试，繁忙数据库可能耗尽预算转人工，未验证生产规模吞吐。
已通过的 operation 不会自动重查；本修复不声称找回此前已被错误清除的 pending。

## 兼容性和未完成边界

- 新增 Alembic `sync_dispatch_receipts`，前序 `upload_idempotency`；只新增请求摘要/任务关联表。
  需显式迁移，服务不会自动改生产库。降级丢失同步请求身份，不能把回退运行当作保留幂等的恢复。
- 同步入口仍不持久化原文，计划落库前退出不自动重跑。租约到期后 `INPUT_UNAVAILABLE`，
  应先核对再以新 key 提交；计划已落库后丢响应可恢复原计划。需要可重跑输入时使用 `/inputs`。
- 历史同步 key 缺少可验证请求身份时拒绝复用；同键异内容/异任务现在明确返回 409。
- 原始上传仍默认存临时目录；本修复检测不可用并停止审批，不自动覆盖、重建文件或修复业务数据。
  生产持久存储、备份/恢复及清理策略仍需部署决策。
- 核验只补齐当前原型 W1 的订单/预占一致性，不增加多仓策略、外部 ERP 对账或物理断电保证。
- 未执行真实浏览器验收、自由中文模型能力评测、付费模型调用、真实客户数据/ERP 操作、合并或部署。
  离线 fixture 成功不是自由语言理解准确率。
